# IR生成
## 1. 整体流程设计
- **入口驱动**：从 `CompUnit` 开始生成 IR，逐层处理 `FuncDef` → `Block` → `Stmt`。
- **分层映射**：将每个 AST 节点类型对应到 IR 生成逻辑：
  - `CompUnit` → 整个程序的入口
  - `FuncDef` → 函数定义
  - `Block` → 函数体代码块
  - `Stmt` → `ret` 返回语句


## 2. 函数定义处理 (`gen_func_def`)
- **确定返回类型**：
  - 根据 `FuncType::Int` 映射为 Koopa 的 `i32` 类型。
- **创建函数对象**：
  - 使用 `builder.new_function` 创建函数，传入函数名（如 `main`）和返回类型。
- **管理上下文**：
  - 设置 `current_func` 和 `current_block`，跟踪当前生成的函数和基本块。

---

### **3. 基本块管理**
- **入口基本块**：
  - 为每个函数自动创建 `%entry` 基本块，作为函数执行的起点。
- **指令插入**：
  - 所有指令（如 `ret`）默认插入到当前基本块（`current_block`）中。
- **终止检查**：
  - 确保基本块以终止指令（如 `ret`）结尾，否则抛出错误（避免生成无效 IR）。

---

### **4. 语句生成 (`gen_stmt`)**
- **返回语句处理**：
  - 从 `Stmt` 中提取 `num` 值（如 `42`），生成 Koopa 整数常量：`new_integer(42)`。
  - 生成 `ret` 指令：`new_ret(常量值, 当前基本块)`。
- **直接映射逻辑**：
  - 由于你的 `Stmt` 仅包含返回数字，无需处理复杂控制流或表达式。

---

### **5. 错误处理与边界检查**
- **上下文校验**：
  - 在生成指令前检查 `current_block` 是否存在（防止在无基本块时生成指令）。
- **终止指令强制要求**：
  - 函数体必须包含 `ret`，否则报错（通过 `current_block_is_terminated` 检查）。

---

### **6. IR 生成结果**
- **文本格式输出**：
  - 通过 `program.to_string()` 将内存形式的 IR 序列化为 Koopa 文本格式。
- **预期输出示例**：
  ```koopa
  fun @main(): i32 {
  %entry:
    ret 42
  }
  ```

---

### **7. 扩展性设计（未来可添加）**
- **符号表**：若添加变量声明，需用 `HashMap` 跟踪变量名到 IR 值的映射。
- **控制流**：处理 `if`/`while` 时需创建多个基本块，并通过 `new_branch`/`new_jump` 连接。
- **表达式计算**：递归处理子表达式，生成 `add`/`mul` 等指令。

---

### **总结**
该生成器的核心思路是 **将 AST 的层次结构逐级映射到 Koopa IR 的内存对象**，通过维护上下文（函数、基本块）确保指令的正确插入，并严格遵循 Koopa IR 的格式规范。当前实现针对你的简化 AST 完成了最小可用版本，后续可在此基础上逐步扩展复杂语法支持。
